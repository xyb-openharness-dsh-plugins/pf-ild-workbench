## 一、临床试验（移植评估 → 临床试验）

三块内容对应用户要求：

1. **基础病理建档** —— 诊断原文 / HRCT 影像结论 / 病理资料（肺活检）/ 遗传·家族史。
   未建结构化字段的如实写作「未建结构化字段」，并说明**缺失的项不是"不符合"**。
2. **检索要素与结果** —— 6 条检索式逐条列命中数与已查/未查通道。
   本轮 6 条里只有「疾病族」1 条命中；5 个通道未查，页面明写**「未查 ≠ 无结果」**。
3. **匹配与分析** —— 每条试验给三档计数（符合 / 冲突 / 待确认）并逐条展开规则：
   规则原文 + 本地对照记录 + 来源；`decidable=0` 的条目单列在「待确认」，不进三档。

**不给百分比、不排序、不推荐。** 三档只能回答"本地记录与条目文字是否一致"，
不构成入组资格判定 —— 这句话同时写在页面顶部、每条试验下和页脚。

## 二、修掉一个真实误判（匹配引擎核心）

两处否定语义没处理，而且**叠加后结论碰巧正确**（四条全绿、看着没问题）：

| # | 位置 | 现象 |
| ① | 事实侧 | 「未在用」被当成事实存在 → 入选条款「正在使用抗纤维化药物」判成**符合**（应冲突） |
| ② | 条款侧 | 「排除…者」没被识别为反向条款 → 「排除 IPF」+ 本地「是（写明 IPF）」判成**符合**（应冲突） |

两边各错一次恰好抵消：条款侧漏判让所有条目走 present 分支，事实侧又把「未在用」算 present。

**只测最终结论抓不到这个。** 所以 `test/trial-match.test.mjs` 逐条测档位并写死反向用例（10 条）。
修复后 A/B 两档案结论不变（符合 4+2 / 冲突 0 / 各 2 条待确认），但现在是逻辑正确得出的。

## 三、数据链路（原先只有引擎和表，三层都没接）
